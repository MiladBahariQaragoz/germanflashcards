# Session Log — 2026-05-25

## What we did

### 1. Reviewed and critiqued system.md + plan.md
- `system.md` described the V1 architecture (single-user, MongoDB Atlas, deployed on Render).
- `plan.md` outlined V2 goals (multi-user, OTP invites, settings menu).
- Identified four real gaps: in-memory queue problem, no migration plan, fragile "first user = admin" logic, and missing per-user kill switch logic.

### 2. Updated plan.md (V2 plan)
Addressed each gap:
- **In-memory queue**: deferred — not a priority right now.
- **Migration plan**: added as Section 2 with three concrete steps (populate `cards`, migrate V1 FSRS progress, create indexes).
- **Admin auth**: removed "first user = admin" logic. Admin stays as hardcoded `AUTHORIZED_CHAT_ID`. New users are invited via OTP only.
- **Kill switch**: explicitly made per-user — lives on `queues[user_id]`, reset per-user on morning trigger, checked per-user on nag runs.

### 3. Fixed system.md deployment info
- Corrected the deployment platform from **Render** to **Google Cloud Compute Engine**.
- VM: `german-bot`, zone `us-central1-a`, project `learn-german-bot`.
- Runs as a `systemd` service. Deployments: Cloud Build trigger → `git pull` + `systemctl restart`.

### 4. Decided to move from MongoDB Atlas to Firestore
**Reason**: everything in one GCP project, no credentials needed (VM service account uses ADC automatically), free tier is more than sufficient, one less external service to manage.

**Trade-off accepted**: `db.py` needed a full rewrite for Firestore's API. `fsrs_service.py` required no changes.

### 5. Rewrote the codebase for Firestore + V2 schema

#### New Firestore collections
| Collection | Purpose |
|---|---|
| `cards` | Global vocabulary (word, translation, sentences, cefr_level) |
| `user_progress` | Per-user FSRS state — one doc per (user_id, card_id) pair |
| `users` | Registered user profiles and preferences |
| `otps` | One-time invite codes generated by admin |

`user_progress` document ID format: `{user_id}_{card_id}` — allows O(1) lookup without a query.  
Vocabulary fields are **denormalized** into `user_progress` so session queries never need a join.

#### Files changed (Firestore rewrite)

**`bot/config.py`**
- Removed `MONGODB_URI` and `DB_NAME`. Firestore uses ADC — no connection string needed.

**`bot/db.py`** — full rewrite
- Uses `google.cloud.firestore.AsyncClient`.
- All functions now accept `user_id` parameter (V2-ready from the start).

**`bot/queue_manager.py`** — per-user refactor
- Replaced module-level singleton with `_sessions: dict[int, SessionQueue]`.
- `get_session(user_id)` creates a queue lazily on first access.
- `reset_all_sessions()` resets all users' queues (called by morning scheduler).

**`bot/handlers.py`**
- Removed `from bson import ObjectId` entirely.
- Card IDs are plain strings throughout (Firestore document IDs).
- Every db call passes `user_id`.

**`bot/scheduler.py`**
- Uses `qm.reset_all_sessions()` and `qm.get_session(user_id)`.

**`scripts/migrate_v2.py`** — full rewrite for Firestore

**`requirements.txt`**
- Added `google-cloud-firestore==2.19.0`.

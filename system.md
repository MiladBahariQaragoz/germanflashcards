# System Architecture: German Flashcards Telegram Bot

This document outlines the architecture, components, and workflows of the German Flashcards bot — a multi-user spaced-repetition study tool built on Telegram.

## High-Level Architecture

An asynchronous Python application integrating with the Telegram Bot API and Firestore. It runs continuously, handling interactive chat events (commands/buttons) and scheduled background jobs (cron tasks).

### Core Technologies
- **Language:** Python 3.11+
- **Bot Framework:** `python-telegram-bot` (v21.5)
- **Database:** Google Cloud Firestore (async client via `google-cloud-firestore`)
- **Spaced Repetition Algorithm:** `fsrs` (Free Spaced Repetition Scheduler)
- **Task Scheduling:** `apscheduler` (AsyncIOScheduler)

### Infrastructure & Deployment
- **Database:** Google Cloud Firestore (native mode, free tier)
- **Application Server:** Google Cloud Compute Engine — VM `german-bot`, zone `us-central1-a`, project `learn-german-bot`. Runs as a `systemd` service (`german-bot.service`). Uses Telegram polling (no exposed web port). Deployments: Cloud Build trigger → `git pull` + `systemctl restart german-bot`.
- **Auth:** VM service account uses Application Default Credentials (ADC) — no Firestore connection string needed.

## Firestore Collections

| Collection | Purpose |
|---|---|
| `cards` | Global read-only vocabulary (word, translation, sentences, cefr_level) |
| `user_progress` | Per-user FSRS state — one doc per `(user_id, card_id)` pair |
| `users` | Registered user profiles and preferences |
| `otps` | One-time invite codes generated by admin |

### `user_progress` document
```json
{
  "user_id": 123456789,
  "card_id": "abc123",
  "word": "Hund",
  "translation": "dog",
  "german_sentence": "Der Hund bellt.",
  "english_translation": "The dog barks.",
  "cefr_level": "A1",
  "fsrs_state": "New | Learning | Review | Relearning",
  "due_date": "<timestamp>",
  "state": 1,
  "step": 0,
  "stability": null,
  "difficulty": null,
  "last_review": null
}
```
Document ID format: `{user_id}_{card_id}` — O(1) lookup without a query.
Vocabulary fields are **denormalized** into `user_progress` so session queries need no joins.

### `users` document
```json
{
  "user_id": 123456789,
  "username": "johndoe",
  "registered_at": "<timestamp>",
  "study_direction": "DE->EN",
  "cefr_levels": ["A1", "A2", "B1", "B2"]
}
```

### `otps` document
```json
{
  "code": "abc123xyz",
  "created_at": "<timestamp>",
  "expires_at": "<timestamp>",
  "used": false
}
```

### Required composite index
```
Collection : user_progress
Fields     : user_id ASC, due_date ASC
```
Create via Firestore console or:
```bash
gcloud firestore indexes composite create \
  --collection-group=user_progress \
  --field-config field-path=user_id,order=ascending \
  --field-config field-path=due_date,order=ascending
```

## Application Components

### 1. Entry Point (`bot/main.py`)
- Initializes `ApplicationBuilder` with `BOT_TOKEN`.
- Registers command handlers: `/start`, `/session`, `/stats`, `/create_invite`, `/login`, `/settings`.
- Registers callback handlers: session flow + settings toggles.
- Starts `AsyncIOScheduler` and begins polling.

### 2. Configuration (`bot/config.py`)
- Loads `.env` via `python-dotenv`.
- Exposes `BOT_TOKEN` and `AUTHORIZED_CHAT_ID`.
- No database URI — Firestore uses ADC automatically.

### 3. Database Layer (`bot/db.py`)
Uses `google.cloud.firestore.AsyncClient`. Functions:

**Session queries**
- `get_due_cards(user_id)` — non-New cards with `due_date <= end_of_today`
- `get_new_cards(user_id, limit, cefr_levels?)` — New cards, optional CEFR filter
- `get_card_by_id(user_id, card_id)` — direct doc lookup
- `update_card_after_review(user_id, card_id, fields)` — apply FSRS update
- `get_card_counts_by_state(user_id)` — counts per FSRS state
- `count_due_cards(user_id)` — total due today

**OTP functions**
- `create_otp(ttl_hours=48)` — generate and store code, return code string
- `consume_otp(code)` — validate + mark used; returns bool

**User functions**
- `register_user(user_id, username)` — create users doc (idempotent)
- `is_registered_user(user_id)` — check existence
- `get_all_users()` — return all user docs (used by scheduler)
- `get_user_settings(user_id)` — return `{study_direction, cefr_levels}`
- `update_user_settings(user_id, fields)` — partial update

### 4. FSRS Service (`bot/fsrs_service.py`)
- Wraps the `fsrs` package.
- `rate_card(card, rating_int)` — calculates next due date for ratings 1–4.
- `preview_intervals(card)` — simulates all 4 ratings to show time strings.

### 5. Queue Management (`bot/queue_manager.py`)
- `SessionQueue` — per-user in-memory study queue.
  - `build(due_cards, new_cards)` — shuffles and combines; caps new cards if due > 150.
  - `pop_next()` — returns next card; drains again_pile when main queue is empty.
  - `add_to_again_pile(card)` — re-queue a card rated "Again".
  - `check_and_set_kill_switch()` — sets kill_switch True when session is complete.
  - `reset()` — clears all state.
- `_sessions: dict[int, SessionQueue]` — per-user registry.
- `get_session(user_id)` — lazy creation.
- `reset_all_sessions()` — called by morning scheduler.

### 6. Handlers (`bot/handlers.py`)
- `_is_authorized(update)` — async; admin bypass + `users` collection check.
- **Commands:**
  - `/start` — greeting; auto-registers the caller in `users`.
  - `/stats` — card counts per FSRS state.
  - `/session` — start study session.
  - `/create_invite` — admin only; generates 48h OTP, prints it.
  - `/login <code>` — validates OTP, registers new user.
  - `/settings` — inline keyboard for study direction + CEFR level toggles.
- **Callbacks:**
  - `start_session` — inline button to begin a session.
  - `show_answer:<id>` — reveal back of card with rating buttons.
  - `grade:<id>:<rating>` — apply FSRS rating, advance queue.
  - `settings_direction` — toggle DE→EN / EN→DE.
  - `settings_cefr:<level>` — toggle a CEFR level on/off.
- Card display (front and back) adapts to `study_direction` preference.

### 7. Scheduler (`bot/scheduler.py`)
- `Europe/Berlin` timezone.
- **Morning Trigger (08:00):** `reset_all_sessions()`, then sends due count + Start button to every registered user plus admin.
- **Nag Check (every 2 h):** per-user check — skips if `kill_switch` is set, otherwise sends remaining count reminder.
- Both jobs iterate `db.get_all_users()` + always include `AUTHORIZED_CHAT_ID`. Per-user `try/except` prevents one failure from blocking others.

### 8. Migration Script (`scripts/migrate_v2.py`)
- One-time script: MongoDB Atlas → Firestore.
- Step 1: reads four JSON files (`combined_words_a1–b2.json`), upserts into `cards` collection.
- Step 2: reads old `flashcards` MongoDB collection, creates `user_progress` docs for admin. Cards with history carry FSRS state; cards still New get blank docs.
- Step 3: prints composite index instructions.

## Workflows

### User Onboarding
1. Admin runs `/create_invite` — bot generates OTP, sends back code.
2. Admin shares code with new user.
3. New user sends `/login <code>` — bot validates, creates `users` doc, confirms registration.

### Session Flow
1. Morning trigger or `/session` command triggers session start.
2. `_start_session` reads user's `cefr_levels` setting, fetches due + new cards accordingly.
3. `queue_manager` shuffles them into a `SessionQueue`.
4. Handler pops first card and sends front (German or English depending on `study_direction`).
5. User clicks "Show Answer" — back is revealed with 4 rating buttons and interval previews.
6. User clicks a rating — FSRS applied, DB updated, next card shown (or session complete).

### Daily Lifecycle
- **08:00 Berlin:** Morning trigger resets all queues, sends due count to every user.
- **Every 2 h:** Nag check reminds users with outstanding cards (skips users with `kill_switch=True`).
- **Session complete:** `kill_switch` set True for that user — silences nag until next morning reset.

## Deployment

```bash
# On the GCE VM
pip install -r requirements.txt

# One-time migration (run once after first deploy)
python -m scripts.migrate_v2

# Create composite Firestore index (once)
gcloud firestore indexes composite create \
  --collection-group=user_progress \
  --field-config field-path=user_id,order=ascending \
  --field-config field-path=due_date,order=ascending

# Restart bot
sudo systemctl restart german-bot
```

> After confirming migration is complete and bot is working, remove `motor` from `requirements.txt`.
